## 第一周：HTTP 语义与网络链路

### Day 1：HTTP 报文与请求方法（P0）

**学习主题**：HTTP 报文结构、请求方法语义、幂等性。

**需要理解的概念**：
- 请求行 / 请求头 / 空行 / 请求体的结构；响应同样四段。
- 7 个常用方法的语义：GET、POST、PUT、PATCH、DELETE、HEAD、OPTIONS。
- 安全方法（不改变服务端状态）vs 非安全方法；幂等的定义与判断。
- Content-Type 与 Accept 的协商机制。

**实操**（20 分钟）：
- 浏览器 DevTools Network 面板查看任一真实请求的完整报文。
- 用 `curl -v https://httpbin.org/get` 观察请求行与头部（为 Day 4 实验预热）。

**当日产出**：`STUDY_NOTES.md`中完成"HTTP 方法语义表"（含幂等性、安全性、典型用途三列）。

**自测验收**（不看资料回答）：
1. 幂等的准确定义是什么？为什么它对重试重要？
2. 写出 GET、POST、PUT、PATCH、DELETE 各自的一个典型业务场景。
3. 请求体和请求头的分界是什么？

**预计用时**：概念 90 分钟 + 实操 30 分钟 + 自测 30 分钟。

---

### Day 2：状态码、头部与缓存（P0）

**学习主题**：状态码分类与高频码、关键响应头、浏览器缓存基础。

**需要理解的概念**：
- 2xx/3xx/4xx/5xx 的分类语义；高频码：200、204、301、302、304、400、401、403、404、409、429、500、502、503、504。
- 301/302/307/308 的方法保持差异。
- 关键头部：Location、Set-Cookie、Cache-Control、ETag、Last-Modified、Content-Type、Server。
- 强缓存（Cache-Control max-age）vs 协商缓存（ETag/If-None-Match）。

**实操**（20 分钟）：
- 用 DevTools 观察一个静态资源的缓存命中（Size 列显示 (disk cache)）。
- `curl -I` 查看响应头，找到 ETag 与 Cache-Control。

**当日产出**：状态码速查表（写进`STUDY_NOTES.md`，标注"哪些码我会在自己的接口里主动返回"）。

**自测验收**：
1. 304 响应有响应体吗？它是怎么被触发的？
2. no-cache 和 no-store 的区别？
3. 用户收到 401 和 403，语义差别是什么？

**预计用时**：概念 90 分钟 + 实操 30 分钟 + 自测 30 分钟。

---

### Day 3：TCP 连接管理（P0）

**学习主题**：三次握手、四次挥手、TIME_WAIT、连接复用。

**需要理解的概念**：
- 面向连接的含义；序列号与确认号的作用。
- 三次握手的过程与"为什么不是两次"。
- 四次挥手的过程与"为什么是四次"；TIME_WAIT 与 CLOSE_WAIT 的含义。
- HTTP/1.1 持久连接（Keep-Alive）与队头阻塞；HTTP/2 多路复用（概念级）。

**实操**：无（纯概念日，用笔画图代替）。

**当日产出**：
- 手绘三次握手与四次挥手状态迁移图（拍照或截图存入笔记）。
- 用自己的话写一段 200 字的"为什么是三次握手"。

**自测验收**：
1. 两次握手会有什么具体问题？（给出一个场景）
2. 挥手第四步的 TIME_WAIT 要等 2MSL，为什么？
3. 服务端出现大量 CLOSE_WAIT 说明什么？（结合"没调 close"）

**预计用时**：概念 120 分钟 + 画图 30 分钟 + 自测 30 分钟。

### Day 4：HTTPS 与 TLS（P0）+ 实验一

**学习主题**：TLS 握手流程、证书链、对称/非对称加密分工。

**需要理解的概念**：
- HTTPS = HTTP over TLS；TLS 握手的目标：协商密钥 + 验证身份。
- 非对称加密（密钥交换）、对称加密（数据传输）、数字签名/证书（身份认证）三者分工。
- 证书链：终端证书 → 中间 CA → 根 CA；浏览器信任根的逻辑。
- TLS 1.2 vs 1.3 的差异只需知道"1.3 更少往返轮次"即可。

**实验**：完成 `experiments/README.md` 中 **实验一：curl -v 观察 HTTPS 握手**。

**当日产出**：实验一记录（含证书 Subject、签发者、有效期的截图或文本）。

**自测验收**：
1. 为什么不能全程用非对称加密传业务数据？
2. 中间人攻击中，攻击者伪造证书为什么会被浏览器拦下？
3. `curl -v` 输出里 `* SSL connection using TLSv1.3` 这类行出现在请求发送之前还是之后？说明什么？

**预计用时**：概念 90 分钟 + 实验 45 分钟 + 自测 30 分钟。

### Day 5：DNS 与全链路串联（P0/P1）

**学习主题**：DNS 解析过程、记录类型、"输入 URL 到响应返回"完整链路。

**需要理解的概念**：
- DNS 递归查询链路：浏览器缓存 → OS 缓存 → hosts → 本地 DNS 服务器 → 根 → 顶级域 → 权威服务器。
- 常见记录：A、AAAA、CNAME、MX、TXT。
- TTL 与 DNS 缓存、解析失败的表现。
- 全链路串联：URL 解析 → DNS → TCP → TLS → HTTP 请求 → 服务端处理 → 响应 → 渲染/回调。

**实验**：完成 `experiments/README.md` 中 **实验二：DNS 解析观察**。

**当日产出**：**全链路手绘图**（本模块最重要的交付物，存入`STUDY_NOTES.md`；每个环节标注"可能失败的表现"）。

**自测验收**：
1. 完整口述从输入 URL 到页面返回的链路（目标 3 分钟内）。
2. ping 得通但 curl 不通，可能是什么问题？
3. CNAME 记录用在什么场景？

**预计用时**：概念 75 分钟 + 实验 30 分钟 + 画图 45 分钟 + 自测 30 分钟。

### Day 6：Linux 基础上半（进程、端口、权限）（P0）

**学习主题**：进程查看与信号、端口占用排查、文件权限。

**需要理解的概念**：
- 进程：PID、父子关系、ps aux 关键列（PID、%CPU、%MEM、COMMAND）。
- 信号：SIGTERM（优雅退出）vs SIGKILL（强杀）；为什么服务要处理优雅关闭。
- 端口：监听态 vs 连接态；`lsof -i:PORT` / `ss -lntp`。
- 权限：rwx 与数字表示（4/2/1）；属主/属组/其他；644、755、600 的语义；目录 x 权限的含义。

**实操**（40 分钟，可选做在 WSL/Linux 或 Git Bash 环境）：
- 启动一个本地服务，用 `ss -lntp` 找到它的 PID。
- 用 `kill -TERM <PID>` 观察优雅退出，对比 `kill -9`。
- 对一个文件执行 chmod，验证不同用户的读写执行。

**当日产出**：命令速查卡（ps/ss/lsof/chmod 各写一条最有用的命令与输出解读）。

**自测验收**：
1. "address already in use" 的排查三步是什么？
2. chmod 600 的文件谁能读写？为什么配置文件常用它？
3. kill -9 有什么副作用？为什么生产上先尝试 SIGTERM？

**预计用时**：概念 75 分钟 + 实操 45 分钟 + 自测 30 分钟。
