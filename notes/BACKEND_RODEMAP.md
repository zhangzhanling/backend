# 任务：制定系统化后端工程学习计划

## 一、我的背景

- 具备 10 年前端开发经验，熟悉 React、Vue、Node.js。
- 有一段 Node.js 业务开发经历，做过业务接口、数据库交互和业务逻辑。
- 当前后端基础：会写接口和基本 SQL，但数据库设计、事务、索引还不扎实。
- 正在求职，目标岗位是全栈开发和 AI 应用开发。
- 需要边投递边学习，不能等全部学完再开始求职。
- 每天可以投入约 2–3 小时。
- 长期目标：真正理解后端原理，具备独立设计、开发、测试、部署、排错和系统设计能力，而不仅仅是会使用框架。

## 二、总体学习路线

按以下顺序逐步学习：

1. 计算机网络、HTTP、Linux 与运行环境
2. 数据库与 SQL
3. Node.js 运行原理与后端工程
4. API 设计、认证授权、安全与测试
5. Redis、缓存、异步任务与并发控制
6. 架构设计、模块化单体、领域建模与系统设计
7. 日志、监控、部署、CI/CD、备份恢复
8. 性能优化、可靠性与高级后端主题

技术主线优先使用 TypeScript、Node.js、PostgreSQL。根据实际需要学习 Redis、消息队列、Docker 和 CI/CD，不要无目的地扩展技术栈。

## 四、计划必须包含的内容

### 1. 学习地图

- 列出本模块的完整知识点树。
- 说明每个知识点的前置知识。
- 区分基础、进阶和高级内容。
- 说明哪些是求职必备，哪些可以后续深入。

### 2. 概念与原理

每个知识点必须解释：

- 是什么，解决什么问题。
- 为什么需要它，出现之前有什么局限。
- 核心工作原理与执行过程。
- 常见误区、边界条件与失败场景。
- 与其他相关技术的区别。
- 面试中可能被追问的问题。

不能只列概念，也不能只给结论。

### 3. 实操与实验

每个重要知识点必须包含：

- 最小可运行示例。
- 逐步操作步骤。
- 预期输出或观察结果。
- 至少一个错误案例或反例。
- 如何验证问题以及如何修复。
- 如何将知识应用到个人 AI 知识库项目中。

涉及数据库时提供 SQL；涉及 Node.js 时提供 TypeScript 代码；涉及部署时提供可执行的命令和验证方法。

### 4. 每日学习计划

按每天 2–3 小时安排，明确：

- 当天学习主题。
- 需要理解的概念。
- 需要完成的实操。
- 当天应提交的代码、实验或文档。
- 自测题与验收标准。
- 预计用时。

先制定一周的详细计划，再根据完成情况逐周推进。不要一开始就输出大量未经验证的每日任务。

### 5. 综合项目

设计一个贯穿本模块的实战任务，说明：

- 业务背景和需求。
- 技术方案与实现步骤。
- 需要交付的代码、设计文档和测试。
- 如何模拟异常、并发、失败或性能问题。
- 项目完成的验收标准。
- 如何把成果转化为简历内容和面试案例。

### 6. 学习深度与验收

每个知识点都必须达到以下闭环：

概念理解 → 原理理解 → 动手实现 → 制造问题 → 定位原因 → 修复问题 → 比较方案 → 面试表达。

每周安排复习和测试。明确哪些内容达到“会用”，哪些达到“理解原理”，哪些需要继续深入。

### 7. 资源与学习方法

优先推荐官方文档、可信的原理资料和高质量实操资源。提供具体章节或页面名称，并说明使用目的。不要堆砌大量链接，也不要为了学习框架而忽略底层原理。

### 8. 求职导向

结合全栈开发和 AI 应用开发岗位，指出：

- 本模块常见面试题。
- 项目深挖时的高频追问。
- 必须能独立回答的问题。
- 面试薄弱时应该如何补强。
