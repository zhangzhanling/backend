# 模块 A：计算机基础与 Web 运行机制 —— 学习方案

## 一、模块定位

### 1. 在整体路线中的位置

- 本模块是总纲建议主路径的**第 1 步**，先于数据库与 Node.js 模块。
- 它不产生直接的项目交付物，但为后续所有模块提供解释能力：
  - 模块 B（数据库）：理解客户端如何把 SQL 请求发到服务端、连接如何建立。
  - 模块 C（Node.js）：理解 HTTP 服务监听端口、事件循环与 I/O 的关系。
  - 模块 D（API 安全）：Cookie/Session/Token/CORS 是认证与安全的直接前置。
  - 模块 G（部署排障）：Linux 进程、端口、权限、日志排查是线上排障的基础。

### 2. 前置知识

- 无硬性前置要求。
- 已具备的可迁移经验：使用浏览器 DevTools 查看网络请求、配置过跨域、写过接口。

### 3. 与其他模块的依赖关系

- 学完本模块 → 才能真正理解模块 D 的认证机制（否则只会"照抄 JWT 代码"）。
- 与模块 C 部分重叠（I/O 模型），本模块只建立概念，Node.js 中的具体机制留到模块 C。
- 与模块 G 部分重叠（Linux），本模块只覆盖排查所需的最小集合。

### 4. 学习性质判定

本模块以**概念和知识点学习为主**，实验仅占约 20% 时间，用于：
- 用 `curl -v` 亲眼观察 HTTP 报文与 TCP/TLS 握手；
- 用 `dig`/`nslookup` 观察 DNS 解析；
- Linux 常用命令的肌肉记忆。

主体是概念体系与面试表达，实验只是"验证概念存在"的辅助手段。

## 三、最应掌握的核心知识点

以下 8 个知识点是本模块的**灵魂**，若只能掌握一部分，优先掌握这 8 个：

### 1. 一个 HTTP 请求的完整生命周期

- 客户端发起 → DNS 解析 → TCP 握手 →（HTTPS 则 TLS 握手）→ 发送请求报文 → 服务端处理 → 返回响应报文 → 浏览器渲染/交给代码 → 连接复用或关闭。
- **必须能画出这条链路**，每个环节说得出"在做什么、失败了会怎样"。

### 2. HTTP 方法语义与幂等性

- GET 安全且幂等、PUT 幂等不安全、POST 不幂等、DELETE 幂等。
- 幂等性是**重试与接口设计**的基础：网络超时后为什么 GET/PUT 可以放心重试而 POST 要小心。
- 这是后续模块 D "幂等键"、模块 E "任务重试"的直接前置概念。

### 3. HTTPS 的三层分工

- 非对称加密（RSA/ECDHE）解决**密钥交换**；
- 对称加密（AES）解决**数据传输效率**；
- 数字证书 + CA 链解决**身份可信**（防止中间人）。
- 常见误区："HTTPS 就是全程加密"——实际上握手阶段用非对称，通信用对称。

### 4. TCP 三次握手 / 四次挥手及原因

- 握手三次：双方确认"我能发、你能收"，且要同步序列号（两次不够的原因要能回答）。
- 挥手四次：TCP 全双工，每个方向要单独关闭（为什么不能像握手那样三次）。
- TIME_WAIT 状态存在的原因（保证最后 ACK 到达、让旧报文过期）。

### 5. Cookie / Session / Token 的协作与取舍

- Cookie 是**传输机制**（浏览器自动携带），Session 是**服务端存储**，Token 是**自包含凭证**。
- Session 方案：服务端有状态，扩容要解决共享（引出 Redis 的需求）。
- JWT 方案：无状态、可水平扩展，但**无法主动失效**是核心代价（引出刷新/黑名单方案）。
- 三者不是互斥的：实际项目常用 "Cookie 携带 JWT" 的组合。

### 6. 同源策略与 CORS 的本质

- 同源 = 协议 + 域名 + 端口全部相同；它保护的是"凭证不被第三方站点盗用"。
- CORS 是**服务端主动声明**的放行机制，不是浏览器的漏洞。
- 简单请求 vs 预检请求（OPTIONS）的判定条件；为什么带 Cookie 要同时配 `withCredentials` 和服务端 `Access-Control-Allow-Credentials`。

### 7. Linux 排查最小集：进程、端口、日志

- 服务起不来 → `ps`/`systemctl status` 看进程；端口冲突 → `lsof -i:端口`；要看日志 → `tail -f`。
- `chmod 644/755/600` 数字含义与安全含义（为什么配置文件不能 777）。
- 这是模块 G 生产排障的地基，也是面试"线上服务 502 你怎么排查"的第一层答案。

### 8. 进程、线程与 I/O 模型的概念分层

- 进程是资源分配单位，线程是调度单位；多进程 vs 多线程的取舍。
- 阻塞/非阻塞（调用立即返回与否）与同步/异步（结果由谁通知）是**两组不同的维度**，面试高频混淆点。
- 为模块 C 的 Node.js 事件循环、模块 H 的并发问题建立坐标系。

## 四、常见误区与易混淆概念

| 误区 | 纠正 |
|------|------|
| HTTPS = HTTP + 加密 | 还包含身份认证（证书）与完整性校验；且加密分对称/非对称两段 |
| 幂等 = 只能调用一次 | 幂等 = 多次调用与一次调用效果相同，可以调用多次 |
| GET 不能有请求体 / POST 不能有查询参数 | 协议不限制，但工具链和实践建议如此（语义问题而非能力问题） |
| 跨域报错是浏览器 bug | 恰恰是浏览器按同源策略正确拦截，绕过同源策略才是 bug |
| CORS 配置在前端 | CORS 响应头由**服务端**返回，前端只是行为上配合（credentials） |
| Session 就是 Cookie | Cookie 是载体，Session 数据实际存在服务端，Cookie 里只有 Session ID |
| JWT 天然比 Session 安全 | JWT 主要解决扩展性；吊销困难反而带来新的安全设计问题 |
| 三次握手是为了"礼貌问候" | 是为了同步双方初始序列号并确认双向可达（各带一个 SYN+ACK） |
| HTTP/2 快是因为压缩 | 头部压缩（HPACK）是其一，多路复用解决队头阻塞是更关键的 |
| 线程比进程一定快 | 线程创建/切换开销小，但共享内存带来同步复杂度；进程隔离性好 |
