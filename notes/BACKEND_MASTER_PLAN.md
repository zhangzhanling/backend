# 后端工程系统化学习总纲（BACKEND_MASTER_PLAN）

## 一、学习背景与个人定位

### 1. 当前技术背景

- 具有约 10 年前端开发经验，熟悉 React、Vue。
- 具有 Node.js 业务开发经历，能够编写业务接口、处理基本 SQL 和业务逻辑。
- 具备一定的全栈开发经验，但后端工程知识尚未形成完整体系。
- 当前需要重点加强数据库设计、事务、索引、并发、安全、系统架构、性能优化和生产环境交付能力。
- 具备前端工程思维，希望将已有经验迁移到后端工程与 AI 应用开发领域。

### 2. 职业目标

以求职为第一目标，同时为后续 AI 应用开发和副业项目积累能力。

重点面向以下岗位：

1. 全栈开发工程师。
2. Node.js 后端开发工程师。
3. AI 应用开发工程师。
4. 具备后端工程能力的 AI Agent 应用开发工程师。

不以成为数据库内核工程师、分布式存储专家或底层基础设施工程师为当前目标，但需要理解相关核心原理，能够进行合理的技术选型和问题分析。

### 3. 学习约束

- 每天投入约 2–3 小时。
- 当前已经开始求职，需要边学习、边做项目、边投递、边面试。
- 不从 JavaScript、TypeScript 或基础编程语法开始学习。
- 不满足于会使用框架或复制代码，必须理解技术背后的原理。
- 所有学习内容都要尽可能转化为可运行的实验、项目成果或面试表达。
- 不追求短期内学完所有知识，而是建立能够持续深化的后端知识体系。

## 二、总体学习目标

最终目标是从“能够开发业务接口的前端工程师”，成长为“能够独立设计、开发、测试、部署、维护和优化后端业务系统的全栈 / AI 应用开发工程师”。

完成学习后，应具备以下能力。

### 1. 数据建模与数据库能力

- 能够根据业务需求设计合理的数据模型、表结构和关系。
- 能够编写复杂 SQL，理解 JOIN、子查询、CTE、窗口函数等常见用法。
- 能够解释索引的工作原理、适用场景和代价。
- 能够使用 EXPLAIN 分析执行计划，定位常见慢查询。
- 能够理解事务、隔离级别、锁、MVCC、死锁和并发更新问题。
- 能够合理设计事务边界，处理重复请求、并发写入和数据一致性问题。
- 能够进行数据库迁移、备份、恢复及基本的容量和连接池管理。

### 2. Node.js 后端工程能力

- 理解 Node.js 运行机制、事件循环、异步 I/O 和 Promise。
- 理解 Stream、Buffer、背压、内存管理及 CPU 密集型任务的处理方式。
- 能够设计清晰的 Controller、Service、Repository 等职责边界。
- 能够组织模块、管理配置、处理异常和实现依赖注入。
- 能够编写结构清晰、可测试、可维护的后端代码。
- 能够理解 Node.js 服务的并发、资源限制和性能瓶颈。

### 3. API 设计与安全能力

- 能够设计规范、稳定、易维护的 REST API。
- 理解参数校验、错误码、分页、过滤、排序、幂等和 API 版本管理。
- 能够实现身份认证、权限控制、角色权限和资源级权限。
- 能够理解常见 Web 安全风险及其防护方法。
- 能够通过自动化测试验证接口行为、异常路径和权限边界。

### 4. 中间件与异步处理能力

- 理解 Redis 的核心数据结构、缓存模式、过期策略和常见问题。
- 能够分析缓存穿透、击穿、雪崩和缓存一致性问题。
- 能够设计后台任务、消息队列、失败重试和死信处理机制。
- 理解幂等、去重、任务状态机、超时和并发控制。
- 能够根据业务需求判断何时使用缓存、队列或定时任务。

### 5. 系统设计与架构能力

- 理解分层架构、模块化单体、领域建模和模块边界。
- 能够识别业务实体、业务规则、事务边界和模块依赖。
- 理解同步调用、异步处理、最终一致性和故障隔离。
- 能够进行基本的容量估算、性能分析和系统方案比较。
- 能够判断何时需要引入缓存、队列、读写分离或微服务，避免无必要的架构复杂度。

### 6. 测试、部署与生产交付能力

- 能够编写单元测试、集成测试和关键业务流程测试。
- 能够使用 Docker 运行和交付后端应用及其依赖服务。
- 能够配置基本的 CI/CD 流程。
- 能够进行日志记录、请求追踪、健康检查和错误排查。
- 能够管理环境配置和密钥，理解基本的生产环境安全要求。
- 能够完成数据库备份恢复、版本发布、故障定位和回滚方案设计。

### 7. AI 应用后端能力

- 能够构建支持大模型调用的后端服务。
- 理解模型 API、结构化输出、超时、重试、限流和成本控制。
- 能够实现文档解析、分块、Embedding、向量检索和 RAG。
- 能够理解检索质量、上下文构造、来源引用和回答评估。
- 能够使用后台任务处理耗时的 AI 工作流。
- 理解工具调用、MCP、Agent 工作流与普通业务 API 的区别。
- 能够为 AI 应用设计权限、安全边界、任务状态、可观测性和故障恢复机制。

## 三、技术选型原则

### 1. 主技术栈

优先围绕以下技术建立统一的学习和项目实践环境：

- 编程语言：TypeScript。
- 运行环境：Node.js。
- 后端框架：优先沿用已有项目中的框架；新建项目时选择 NestJS 或 Express 之一。
- 关系型数据库：PostgreSQL。
- SQL 学习方式：先掌握原生 SQL，再学习 ORM。
- ORM：选择 Prisma 或 Drizzle 之一，不要求同时深入两套。
- 缓存：Redis。
- 异步任务：选择与项目相匹配的任务队列，例如 BullMQ。
- API 风格：以 REST 为主。
- 自动化测试：采用所选框架生态中成熟的测试工具。
- 部署：Linux 基础、Docker、CI/CD。
- AI 应用：模型 API、Embedding、向量检索、RAG，后续再深入 Agent 和 MCP。

### 2. 技术选型原则

- 同一阶段尽量只使用一套主要技术，减少切换成本。
- 不为了学习而堆叠技术，不将微服务、Kubernetes 或复杂消息系统作为入门前提。
- 先掌握技术解决的问题，再学习具体工具。
- 优先使用稳定、成熟、易于求职展示的技术。
- 对关键技术保留替代方案认知，但不要求同时实现多个版本。
- 所有技术选择都需要能够解释其适用场景、优缺点和引入成本。

## 四、完整知识体系与学习模块

所有模块都必须覆盖概念、原理、实践、工程应用、问题排查和面试表达。

### 模块 A：计算机基础与 Web 运行机制

学习内容：

- HTTP/HTTPS、请求响应、常见状态码和请求方法。
- DNS、TCP、TLS、连接建立与关闭。
- Cookie、Session、Token、跨域、CORS。
- 浏览器与服务端的交互流程。
- Linux 进程、端口、文件权限、环境变量和常用命令。
- 操作系统中的进程、线程、I/O 和基本资源管理。

目标：能够解释一个请求从客户端发出，到服务端处理，再到响应返回的完整过程，并具备基础的线上排查能力。

### 模块 B：关系型数据库与 SQL

学习内容：

- 关系型数据库的基本模型与 PostgreSQL 基础。
- 实体关系、主键、外键、唯一约束、非空约束和检查约束。
- 一对一、一对多、多对多关系设计。
- 规范化、冗余字段、反规范化及其取舍。
- 数据类型、NULL、默认值和约束语义。
- INSERT、UPDATE、DELETE、SELECT。
- JOIN、子查询、CTE、聚合和窗口函数。
- 分页、排序、过滤和批量操作。
- 索引结构、B-tree 索引、联合索引、部分索引及索引代价。
- EXPLAIN、EXPLAIN ANALYZE 与执行计划分析。
- 事务、ACID、隔离级别、锁、MVCC、死锁。
- 并发更新、乐观锁、悲观锁和数据一致性。
- 连接池、慢查询、迁移、备份、恢复和数据库安全。

目标：能够独立完成中等复杂度业务的数据建模、SQL 编写、查询优化和事务设计，并能通过实验解释关键机制。

### 模块 C：Node.js 运行机制与工程设计

学习内容：

- Node.js 运行时与 V8 的基本职责。
- 事件循环、任务队列、Promise 和异步 I/O。
- 并发与并行的区别。
- Stream、Buffer、背压和大文件处理。
- CPU 密集任务、Worker Threads 和进程管理。
- 内存使用、资源释放和常见内存泄漏问题。
- 模块化、依赖管理和配置管理。
- Controller、Service、Repository 的职责划分。
- 依赖注入、异常处理和统一响应。
- 日志、校验、可测试性和代码组织。
- 优雅关闭、连接释放和服务生命周期。

目标：能够解释 Node.js 的关键执行机制，并编写结构清晰、可测试、可维护的后端应用。

### 模块 D：API 设计、身份认证与安全

学习内容：

- REST API 设计规范。
- 参数校验、序列化、分页、过滤和排序。
- 统一错误处理、错误码和日志关联。
- API 版本管理与兼容性。
- 身份认证、授权和资源级权限。
- Session、JWT、密码哈希、刷新机制和会话失效。
- RBAC、数据权限和租户隔离的基本设计。
- SQL 注入、XSS、CSRF、SSRF、文件上传风险。
- 限流、请求大小限制、敏感信息保护和安全配置。
- 幂等键、重复提交、并发写入和接口重试。
- 单元测试、集成测试和 API 自动化测试。

目标：能够实现安全、稳定、可测试的业务 API，并解释关键安全决策的原因。

### 模块 E：Redis、缓存与异步任务

学习内容：

- Redis 常见数据结构及其适用场景。
- 缓存读写模式、过期策略和失效机制。
- 缓存穿透、击穿、雪崩及缓存一致性。
- 分布式锁的使用边界与常见误区。
- 队列、后台任务和异步工作流。
- 任务状态、超时、重试、退避、去重和幂等。
- 死信处理、任务补偿和失败恢复。
- 数据库与消息队列之间的一致性问题。
- Outbox 等可靠事件投递模式的基本原理。
- 定时任务、并发控制和任务可观测性。

目标：能够设计可靠的后台任务系统，正确处理失败、重试、重复执行和任务状态恢复。

### 模块 F：架构设计与系统设计

学习内容：

- 分层架构、模块化单体和模块边界。
- 领域建模、实体、值对象、业务规则和领域服务。
- 业务流程、事务边界与数据所有权。
- 依赖方向、模块耦合和代码组织。
- 同步调用与异步处理。
- 最终一致性、补偿机制和故障隔离。
- 数据库、缓存和队列的协同设计。
- 基本容量估算、并发量估算和存储估算。
- 性能瓶颈定位与架构演进。
- 读写分离、分区、微服务和分布式系统的适用条件。
- 技术方案比较、复杂度评估和工程取舍。

目标：能够从业务需求出发设计合理的系统结构，而不是仅根据技术流行度选型。

### 模块 G：测试、部署、可观测性与运维

学习内容：

- 单元测试、集成测试、端到端测试。
- Mock、测试数据、测试隔离和测试环境管理。
- Linux 下的进程、端口、日志和资源排查。
- Docker 镜像、容器、网络、卷和环境配置。
- 多服务本地开发环境与部署。
- CI/CD、自动化测试和发布流程。
- 配置管理、密钥保护和环境隔离。
- 结构化日志、请求 ID、指标、Trace 和错误追踪。
- 健康检查、优雅关闭和依赖服务检查。
- 数据库备份、恢复验证、发布回滚和故障演练。
- 基础性能监控与容量观察。

目标：能够将应用从本地开发推进到可重复部署、可观测、可排障和可恢复的运行状态。

### 模块 H：性能、可靠性与进阶后端知识

学习内容：

- 慢查询与执行计划优化。
- 连接池、并发控制和资源使用。
- 缓存策略与热点问题。
- Node.js CPU、内存、I/O 性能问题。
- 超时、重试、限流、熔断和故障隔离。
- 服务容量估算与性能测试。
- 数据库复制、分区和数据增长策略。
- 分布式一致性、消息投递语义和幂等。
- 可用性、恢复目标与故障分析。
- 复杂系统中的权衡与渐进式演进。

目标：具备常见性能与可靠性问题的分析能力；进阶知识按求职需求和项目复杂度逐步深入，不要求一次性全部精通。

### 模块 I：AI 应用后端工程

学习内容：

- 大模型 API 调用与统一模型服务封装。
- Prompt、结构化输出和模型响应校验。
- 超时、重试、限流、成本控制和模型降级。
- 文档上传、解析、分块和元数据管理。
- Embedding、向量存储、相似度搜索和混合检索。
- RAG 检索、上下文构造、来源引用与回答评估。
- 异步文档处理、任务状态和失败恢复。
- 工具调用、工作流编排、Agent 与 MCP 的基本原理。
- AI 应用中的权限、数据隔离、提示注入和敏感信息保护。
- AI 请求日志、调用追踪、延迟、成本和质量评估。

目标：能够构建具备真实后端工程质量的 AI 应用，而不只是完成一次大模型 API 调用。

## 五、模块之间的依赖关系

学习顺序必须考虑知识依赖，不应完全按照技术名称逐个学习。

建议主路径：

1. 计算机基础与 Web 运行机制。
2. 数据建模与 SQL。
3. Node.js 运行机制与工程设计。
4. API 设计、认证、权限和测试。
5. 事务、并发与数据库优化持续深化。
6. Redis、缓存和异步任务。
7. 架构设计与系统设计。
8. 测试、部署、可观测性与运维。
9. 性能、可靠性和进阶后端知识。
10. AI 应用后端工程贯穿实践，并随基础能力逐步升级。

说明：

- SQL 与 Node.js 可以交叉学习，但数据库设计和事务必须在复杂业务开发之前得到足够训练。
- 安全、测试和错误处理不能等到项目最后才考虑。
- Docker、日志和 CI/CD 应尽早进入项目，随后逐步完善。
- AI 应用可以从早期开始做最小原型，但生产级 RAG、异步处理和 Agent 工程应建立在 API、数据库、任务系统与安全基础之上。
- 实际求职中发现的薄弱点可以调整学习顺序，但不能因此长期跳过基础模块。

## 六、贯穿全程的主项目

使用一个持续迭代的“个人 AI 知识库系统”作为主要工程实践项目。

项目应包含以下能力：

### 1. 核心业务

- 用户与身份认证。
- 知识资源的新增、查询、修改和删除。
- 标签、分类、收藏集等关联关系。
- 文档上传、内容解析和状态管理。
- 关键词搜索与向量检索。
- 基于知识库的 RAG 问答。
- 回答来源与引用片段展示。
- 后台任务状态、失败重试和重新处理。
- 用户数据隔离与资源级权限。

### 2. 后端工程要求

- 使用 PostgreSQL 设计核心数据模型。
- 使用迁移管理数据库结构变化。
- 为关键查询设计并验证索引。
- 对涉及多条数据变更的业务正确使用事务。
- 对并发更新和重复请求设计明确的处理方式。
- 为关键 API 编写测试。
- 为后台任务设计幂等、重试和失败恢复机制。
- 使用结构化日志和请求 ID 定位问题。
- 使用 Docker 交付可重复运行的环境。
- 配置基本 CI/CD。
- 编写 README、架构说明、API 文档和部署说明。
- 提供备份恢复与故障排查说明。

### 3. 项目阶段验收

M1：数据库基础

完成 ER 图、数据字典、建表 SQL、约束设计、核心查询和基础索引方案。

M2：业务 API

完成主要 CRUD、参数校验、统一错误处理、身份认证、权限控制和 API 测试。

M3：事务与并发

通过实验验证事务回滚、并发更新、唯一约束、死锁或冲突处理；能够解释所采用的策略。

M4：异步任务

完成文档解析队列、任务状态、幂等、重试、失败恢复和任务观测。

M5：AI 检索

完成文档分块、Embedding、检索、RAG 回答和来源引用；建立基本的检索与回答质量评估样例。

M6：生产交付

完成 Docker 部署、自动化测试、CI/CD、日志、健康检查、数据库备份恢复和故障排查文档。

每个阶段都必须留下可检查的交付物，不能仅以“学过相关知识”作为完成标准。

## 七、统一学习方法

所有学习模块必须遵循以下闭环：

1. 业务问题：理解技术要解决的真实问题。
2. 核心概念：明确术语、组成部分和基本规则。
3. 底层原理：理解运行机制、执行过程和设计原因。
4. 最小实验：通过代码、SQL 或命令验证原理。
5. 反例实验：主动制造错误、边界情况或故障。
6. 工程实践：将知识应用到主项目。
7. 方案比较：了解替代方案及其优缺点。
8. 面试表达：能够在 1–3 分钟内解释概念、原理、场景和取舍。
9. 复盘巩固：不看教程重新实现，并记录容易混淆的知识。

每个重要知识点至少回答以下问题：

- 它是什么？
- 它解决什么问题？
- 为什么需要它？
- 它的工作原理是什么？
- 具体执行过程是什么？
- 在什么情况下适用？
- 有哪些限制和代价？
- 常见错误是什么？
- 如何通过实验验证？
- 在实际项目中如何应用？
- 面试官可能从哪些角度追问？

学习资料可以帮助理解，但不能替代独立实验和实际交付。
